## What was built

- **Library** `src/voice-decide.mjs` — `decideWithVoice()` answers a
  pending GhostGuard `ask`/`hand_off` record from a JSONL trail
  (bare gateway records and Cloud-wrapped `{entry_type:"record",
  record}` lines both accepted). It copies the voice recording
  verbatim to an evidence folder, hashes its bytes
  (`audio_sha256`), hashes the ask's canonical `action_payload`
  (`payload_sha256`), and appends ONE decision entry to a decisions
  JSONL in GhostGuard Cloud's decision shape plus voice fields.
  Also `listPending()` and `verifyEvidence()` (re-hash stored
  recordings, report mismatches/missing files).
- **CLI** `src/cli.mjs` — `pending` / `decide` / `verify` commands.
- **Hashing** `src/hash.mjs` — canonical JSON (sorted keys) + SHA-256
  via `node:crypto`. Zero runtime dependencies, Node ESM.
- **SPEC.md** — MrGhosty integration path (phone records → decision
  entry → Cloud `waitForDecision` wakes the waiting agent), staged
  identity roadmap, spoofing cautions.
- **README.md** — leads with the honest identity statement:
  **voice-match identity is NOT implemented**; v1 is voice as the
  channel, the human's device/recording as the evidence.

## Safety properties (all enforced in code and tested)

- Only `ask` / `hand_off` verdicts are decidable — a voice approval
  for a `deny`-verdict action errors; voice can never override policy.
- Unknown `action_id` errors; already-decided actions error
  (decisions are append-only, no re-deciding).
- Failed decisions write nothing (no entry, no evidence copy).
- The trail file is never modified by a decision.
- Recordings are treated as opaque bytes: never transcribed, never
  altered — the evidence copy is byte-identical to the input.

## Verification

Command: `npm run verify` (= `node test/run-tests.mjs`) in
`~/workspace/ghostguard-voice` — **14 passed, 0 failed:**

1. approve appends a decision entry with the Cloud decision shape + voice fields
2. entry is bound to the ask's exact payload hash
3. audio_sha256 is the hash of the recording bytes; evidence copy is byte-identical
4. the trail file itself was not modified
5. deny decision on a hand_off record is recorded as a deny
6. unknown action_id errors and writes nothing
7. deciding an already-decided action errors; decisions file unchanged
8. voice-approving a deny-verdict action errors — voice never overrides policy
9. an allow-verdict action is not decidable either
10. verify passes on untouched evidence
11. tampering with the stored recording afterwards is detected by verify
12. CLI verify exits 1 and names the mismatch after tampering
13. CLI decide records an approval end-to-end; pending no longer lists it
14. decide never rewrites the trail (append-only history stays intact)

Fixture audio: a synthetic WAV generated byte-by-byte in the test
(RIFF header + silent PCM samples) — no speech, not any person's
voice, labelled as synthetic in the test source.

## Left undone (by design, stated in SPEC.md)

- No transcription — the tool cannot confirm a recording's words;
  the recording is evidence for a human reviewer.
- No voice-match / biometric identity — explicitly out of v1; the
  roadmap stages it as a possible v2 *additional* signal with
  challenge phrases and measured error rates, never the sole gate.
- No MrGhosty or GhostGuard Cloud wiring — local JSONL only; the
  integration is specified, not built.
- No hash-chaining/signing of entries; evidence tampering is
  *detected* by re-hash, not prevented.
